# M6809E Decoder Walkthrough

I have implemented the 6809E instruction decoder in the new `lib/decode_m6809e.go` package, alongside comprehensive tests.

## Changes Made

- **Decoder Implementation**: Added `lib/decode_m6809e.go` which exposes `Decode(mem []byte) (disasm string, numBytes int, numCycles int, cycleCodes string, ok bool)`.
- **Instruction Tables**: Fully modeled the entire 6809 instruction set spanning across Page 1, Page 2 (0x10), and Page 3 (0x11). It decodes addressing modes (Immediate, Direct, Extended, Indexed, Relative, Inherent) and handles edge cases dynamically (e.g. `PSHS`/`PULS` variables).
- **Cycle Strings generation**: Following your rules:
  - `o`: Opcode fetches
  - `p`: Address/Operand fetches
  - `r`/`w`: Extra reads and writes (e.g., pulling/pushing, memory read/write)
  - `-`: VMA/internal idle cycles
  - Taken/not taken branch times use the maximal time (e.g., `LBxx` branches report 6 cycles instead of 5).
  - Variable time instructions like `CWAI` and `SYNC` use their minimum base times (20 and 2 cycles).
  - `ok = false` is safely returned for incomplete memory boundaries or illegal instructions.
- **Generator Script**: The go code is fully autogenerated by an easily maintainable python script placed in `doc/gen.py`. You can adjust core metrics or rules in `gen.py` and run it to rebuild the decoder if necessary.

## Testing and Verification
- Wrote `lib/decode_m6809e_test.go` verifying output permutations.
- Checked boundaries, multi-byte decoding (Page 2 & 3 prefixes), memory-intensive instructions (`PSHS`, `CWAI`), and proper cycle-by-cycle rendering (like `LDA 16-bit offset` emitting `oppp---r`).
- Passed all unit tests.
